# 贝果位置与朝向说明

本文说明贝果局内小地图的镜头朝向识别、转向校准与截图时序。画面事实见[贝果计划画面](../../../game/screens/贝果计划.md)，自动化调用见[贝果应用](bagel.md)。朝向识别代码在 `src/zzz_od/game_data/map_locator/minimap_angle.py`。

## 1. 方向与几何模型

### 两种方向

- 小地图中心的黄色箭头表示角色朝向。箭头位置大致固定，形状随角色转身旋转。
- 外围半透明黄色扇区表示镜头朝向。转动镜头可以只改变扇区方向，因此箭头不能用于判断镜头方向。

角度统一为正右 0 度、逆时针增加，范围 `[0,360)`。`analyze` 只识别镜头朝向：返回元组的第三项是镜头朝向，第五项是固定采样圆心，前两项恒为 `None`，第四项恒为 0.0。进电梯后小地图整块消失，导航用朝向是否为 `None` 判断进出电梯。

### 裁剪与采样圆心

定位小地图的整屏裁剪区域为 `[1533,206,1734,407)`，大小 201×201。坐标统一使用裁剪内像素下标：左上像素中心为 `(0,0)`，X 向右、Y 向下。

采样圆心 C 是裁剪像素中心 `((201−1)/2, (201−1)/2) = (100,100)`。采样时将 C 加径向偏移后取整为数组下标，所以 C 必须按像素下标表示；在公式里再加 0.5 会实际移动采样位置。改裁剪范围也会改变像素中心：例如右下端点各减 1 得到 200×200，像素中心变为 `(99.5,99.5)`。调整裁剪范围与调整采样圆心须分别评估。定位模块独立使用裁剪像素中心，不读取朝向函数返回的圆心。

### 扇区几何

以下模型来自图像拟合，不是游戏内部坐标：

| 对象 | 定义 | 估计值 |
| --- | --- | --- |
| 人物位置 P | 不同方向扇区中线的公共点；小地图随人物平移，P 在裁剪内大致固定 | 约 `(99.92,99.28)`，距 C 约 0.72 像素 |
| 扇区顶点 A | 扇区两条直边延长后的交点 | `A = P + k × (cos θ, −sin θ)`，θ 为镜头方向 |
| 顶点前移 k | A 沿镜头方向在 P 前方的距离 | 模型取 2.83 像素 |
| 顶点张角 | 两条直边在 A 处的夹角 | 模型取 116.7 度 |

镜头转动时，A 绕 P 移动。逐帧自由拟合两条直边时，411 帧的张角中位数为 116.68 度，90% 落在 115.4～117.4 度，各方向均值相差不到 1 度。k 的中位数为 2.69 像素，90% 落在 2.41～3.45 像素；朝东、北、西、南的均值约为 3.17、2.64、2.51、3.07 像素，且与张角的相关系数约为 0.81。k 依赖边缘取在颜色过渡的哪个位置，随方向变化的原因尚未确认，可能来自 P 的估计误差或不同方向的抗锯齿差异。

采样角宽是从采样圆心看扇区与某条采样圆交点形成的夹角。采样圆心在 A 后方，因此采样角宽小于顶点张角。令采样圆心等于 P、半张角为 α 时，半径 r 上的采样角宽为：

```text
W(r) = 2 × [α − arcsin(k × sin(α) / r)]，k ≈ 2.83 像素，α ≈ 58.35 度
```

| 采样半径 r | 22 像素 | 23 像素 | 28 像素 | 33 像素 |
| --- | --- | --- | --- | --- |
| W(r) | 约 104.1 度 | 约 104.7 度 | 约 106.8 度 | 约 108.3 度 |

## 2. 识别步骤

1. 将 RGB 图转成 HSV。H 是色相，S 是饱和度。只保留 `14 ≤ H ≤ 34` 的像素，以 S 作为得分，其他像素得分为 0。整张图没有正得分时返回 `None`。
2. 以 C 为圆心，每圈按 1 度步长采样 360 个位置。坐标用 `np.round` 取整后直接读取像素，不插值。
3. 计算每个连续 117 点窗口的得分和，找出最高分。多个相邻起点并列最高时，从第一个最高分起点向两侧扩展，按圆周找出它所在的连续并列段，跨越 0/360 度时同样相连，取该段中点作为起点。全圈得分相同时，退回第一个起点。
4. 单圈方向为起点加 `(117−1)/2 = 58` 度，再折回 `[0,360)`。
5. 先计算半径 23、28。两圈最短角差不超过 3 度时，返回两者的方向向量平均值。
6. 否则依次增加半径 24、30、22、26、25、27、29、31、32、33。每加一圈，按已有读数顺序寻找候选；至少三个读数距同一候选不超过 4 度时，返回这组读数的方向向量平均值。
7. 用完所有圈仍找不到这样的组时，返回全部读数的方向向量平均值。

## 3. 设计依据

- **先筛黄色再取饱和度**：蓝色底图饱和度也高，不筛色相会把方向拉偏。黄色场景底色也能通过筛选，所以不能完整分离扇区与背景。
- **滑窗**：寻找最亮像素或黄色质心，容易被箭头、墙面和图标带偏；一般边缘检测会同时提取墙线和地板纹理。累积和滑窗计算量小，适合做方向估计。
- **采样圆心取 `(100,100)`**：C 偏离 P 时，读数偏差随镜头方向近似按正弦变化。只考虑圆心位置时，C 的偏差幅度约为 ±0.86 度。把圆心改到 P 不能消除下面的并列偏差。
- **并列取中点**：117 点窗口宽于 W(r)，可以在一段起点范围内完整罩住扇区，这些起点得分并列，半径 23、28 上约有 13、11 个。扇区对称于中线，采样圆心在中线上时，并列段中点加窗口半宽正好落在扇区中线，这一点与 W(r) 无关，因此不依赖 k 和张角。取第一个起点（`np.argmax` 的默认行为）会偏小约并列段长度的一半，偏差随 k、张角和半径变化。
- **加 58 度**：117 个采样点覆盖下标 0～116，中点是 58；加 `117/2 = 58.5` 会多出 0.5 度。两项必须同时使用：只改加 58 度而仍取第一个起点，读数会更小。
- **只取一段并列段**：不相连的并列段可能代表不同方向，不能把全部最高分起点平均。

可重建的合成输入：201×201 图，P 与 C 均为 `(100,100)`，按上节模型生成扇区（距 C 18～45 像素），背景为 OpenCV HSV `(0,0,35)`，扇区为 `(24,180,180)`。θ 为 180 度时，取第一个起点加 58.5 度的规则读成 175.5 度，当前规则读成 180 度。遍历 360 个整数方向，前者平均偏小约 4.97 度，当前规则平均绝对误差约 0.27 度、最大 0.75 度；令 k 在 0～4 像素、张角在 112～122 度之间变化，当前规则的结果不变。

在未归档的研究样本上，相对图像拟合的参考方向（不是游戏真值），两种规则的绝对误差如下：

| 样本 | 第一个起点 + 58.5 度：均值 / P90 / 最大 | 并列段中点 + 58 度：均值 / P90 / 最大 |
| --- | --- | --- |
| 无损截图 296 张 | 3.94 / 4.38 / 6.75 度 | 1.10 / 1.26 / 7.73 度 |
| 录屏 397 帧 | 2.80 / 6.41 / 11.06 度 | 1.27 / 2.77 / 9.10 度 |
| 录屏 16 帧（镜头与角色各朝四向） | 3.48 / 6.31 / 7.32 度 | 1.79 / 3.36 / 4.46 度 |

这些结果只用于设计比较，不能替代实机验收。

## 4. 已知限制

- **离群读数**：遮挡、黄色底色和图标仍会造成数度误差。无损样本的最大误差在改用并列中点后没有下降，录屏仍约有 8% 的帧超过 3 度。
- **有数值不代表可信**：有效性检查只看整张图有没有通过色相筛选的像素。黄色像素只在采样圆外时，各圈全圈同分，都读成 58 度并被当作一致读数；黑图仅在 `(5,5)` 放一个 RGB `(255,204,0)` 像素即可重建。
- **多圈规则偏宽**：第 6 步是“距候选不超过 4 度”，组内两个读数最多可相差约 8 度，例如 0、4、356 度。不收敛时仍输出全部读数的平均值。半径 23、28 相邻，可能受同一片背景干扰。
- **采样精度**：1 度步长不等于 1 度精度。半径 23～28 处沿圆周移动 1 像素约对应 2.0～2.5 度，取整会重复读取像素并产生跳变。
- **固定偏差无法靠校准消除**：读数有固定偏差时，导航按偏差后的读数修正，实际镜头仍偏离目标；转向校准只比较转向前后的读数差，看不到这类偏差。

精度目标为误差不超过 3 度，当前实现不保证达到该目标。

## 5. 转向校准与截图时序

校准逻辑在 `src/zzz_od/application/bagel/bagel_input_worker.py`，局末写回在同目录的 `bagel_route_walker.py`。

### 实时校准

转向线程比较转向前后的稳定朝向。实际转角小于 3 度、下发转角小于 8 度、方向相反，或比例超出 `[0.2,20.0]` 时，样本不计入。实际转角小于 0.5 度时，先等待画面变化，超时后放行下一次转向。

有效样本的比例 `r = abs(实际转角) / abs(下发转角)`：

1. 以 1.0 为一个箱的中心、0.05 为箱宽分箱，箱号为 `floor((r−1)/0.05 + 0.5 + 1e−9)`。
2. 该箱计数加一。只有某个箱的计数超过当前最高计数，才切换到它；同分时保留当前箱。
3. 选中箱的中点作为 `turn_ratio`，下一次下发角为期望转角除以它，再执行原有幅度上限。
4. 同时保存原始补偿比例 `1/r`，供局末统计。

计数覆盖本局全部有效样本，没有时间衰减。

### 局末写回

有效样本达到 10 个后，把原始 `1/r` 重新按 0.05 分箱，取频数最高箱的中点；同分时取最早出现的箱。结果在 `[0.55,1.95]` 内且与 1.0 相差至少 0.03 时，`turn_dx` 乘以该值，保留六位小数。

已知限制：

- 不检查峰值占比。原始补偿依次为 `0.60、0.70、…、1.50` 时，10 个箱各一个样本，仍会选出 0.60 并写回。
- 实时与局末在倒数两侧分别分箱，结果不一定互为倒数。10 个样本均为 `r=1.30` 时，实时补偿约 0.76923，局末写回 0.75。

### 截图缓存与判稳

`src/one_dragon/base/controller/pc_screenshot/pc_screenshot_controller.py` 按独立模式、是否缩放和窗口矩形分别缓存截图。同一缓存键在采集后 `1/30` 秒内直接返回同一张图；独立截图与主线截图不互相命中。

转向线程约每 0.03 秒采样一次，主线提交目标时会提前唤醒它；下发转向后 0.3 秒内不采样，主线不受停采限制。线程按最近三张不同截图的读数判稳，相邻角差不超过 1 度即稳定。截图缓存返回与上次相同的图像对象时，这次采样不计入，已有读数和静止计时都保持不变。已知限制：

- 去重只比较截图对象。两次分别采集的截图如果显示同一游戏画面，仍各算一帧。
- `ControllerBase.screenshot()` 命中缓存时也返回本次请求的时间。0 ms 采集 A、10 ms 松键、20 ms 请求时，返回 A 但时间为 20 ms；只比较返回时间与松键时刻，会把动作前的画面当作动作后的画面。

## 来源与复核范围

- **裁剪区域**：可从 Git 复核。最早贝果配置提交 `4ee0b381` 已使用上述 201×201 区域；最早定位提交 `72c5ab59` 的 `route.yml` 将 `anchor_xy` 和 `mask.center_xy` 设为 `[100,100]`。记录没有说明裁剪端点的测量方法，不能据此断言人物位置精确等于裁剪中心。
- **P 的估计**：在 Lab 色彩空间的 b* 通道上，沿半径 18～48 寻找扇区两侧边缘点，用 RANSAC 拟合两条直边，再对多帧中线求最小二乘公共点。样本为 296 张 1080p 无损截图，未归档。
- **归档粗检**：[出生点素材索引](../../../game/screens/image/bagel_spawn_points/README.md)中的五张 `*_hud.webp` 重做中线公共点拟合，P 约为 `(99.7,99.3)`；WebP 有损压缩，单张张角为 110～121 度，只能粗检。工地深处与六昏街南站归档图的半径 23、28 上也存在 3～8 个并列最高分起点。
- **研究样本限制**：无损截图、录屏两组集合方向分布不均，录屏相邻帧不独立；录屏参考方向是固定 k 与张角的约束拟合，与无损截图的自由拟合不是同一种估计。合成输入用于确认机制，归档图片用于粗检画面，两者都不能替代实机验收。
