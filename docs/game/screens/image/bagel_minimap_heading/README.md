# 贝果小地图镜头朝向素材

本目录是镜头朝向识别的离线对比基准。调整 `src/zzz_od/game_data/map_locator/minimap_angle.py` 前后，在同一组图上比较误差。识别规则见[镜头朝向说明](../../../../develop/zzz/application/bagel_heading_observation.md)。这组素材只比较算法版本之间的相对优劣，不代替实机验收。

## 内容

57 张 201×201 图，均从 1920×1080 无损截图裁剪小地图矩形 `[1533,206,1734,407)`，未缩放，保存为无损 WebP，解码后与裁剪像素逐一相同。裁剪范围不含账号标识（UID），未做遮挡。原始整屏截图未归档。

补充素材必须无损保存。实测质量 90 的有损 WebP 会让读数最多变化约 3 度，并让局内背包、局外菜单画面误读成 58 度。

- 50 张有参考方向，文件名为 `<场景>_<参考方向取整>.webp`。
- 7 张以 `none_` 开头，画面上没有可读的小地图，期望读不到朝向。

## 参考方向

参考方向由图像拟合得到，不是游戏真值：

1. 以角色标记质心为暂定圆心，在半径 18～48 上采集 Lab 色彩空间 b* 通道（黄-蓝轴）的剖面，找出扇区两侧的边缘点。
2. 两侧边缘点分别用 RANSAC 拟合直线。两条直线的夹角平分线即参考方向，夹角即张角，交点即扇区顶点。
3. 两侧各有不少于 10 个边缘点、残差小于 0.5 像素时才入选，再人工逐张核对参考线与扇区中线是否重合。张角明显偏离的拟合（例如约 105 度）已剔除。

入选图的张角为 113.9～117.5 度，残差最大 0.37 像素。

人工复核：在 2 张普通图（`open_270`、`wall_000`）和 5 张 `pink` 图上，人工沿扇区两条边点出边缘点，各拟合一条直线，取夹角平分线。人工方向与拟合参考相差：普通图 0.03～0.12 度，`pink` 图 0.16～1.68 度。人工结果记录在 `manual` 字段。

## frames.json

每张图一条记录：

- `file`：文件名。
- `scene`：场景，取值同上表。
- `reference`：参考方向，单位为度，正右为 0，逆时针增加；`null` 表示期望读不到朝向。
- `manual`：人工标注的方向，只有人工复核过的图才有。
- `fit`：拟合结果。`width` 为张角（度），`rms` 为两侧残差中较大者（像素），`apex` 为扇区顶点在裁剪图中的坐标。
- `note`：补充说明。
- `source`：来源。`type` 为采集方式，`name` 为原始文件名，`captured` 为采集时间。

采集方式：

- `调试截图键`：一条龙调试截图键保存的整屏图。
- `应用自动调试截图`：贝果应用运行时自动保存的整屏图。
- `MCP 截图`：通过 MCP 截取的整屏图。

## 计算方法与当前基线

逐张用 `analyze` 读朝向：

- 有参考方向的图：求圆周差 `(读数 − 参考 + 180) mod 360 − 180`，统计绝对值的平均、95 分位和最大值。
- `none_` 图：检查是否返回 `None`。

并列取中点版本（提交 `ca78d696`）的结果如下：

- 50 张有参考方向的图：平均绝对误差 1.19 度，95 分位 3.99 度，最大 7.73 度（`pink_282.webp`）。
- 误差不小于 3 度的 5 张都是 `pink`，读数都偏大，偏差为 3.4～7.7 度。以人工标注为参考时偏大 2.5～8.4 度，其中 `pink_282`、`pink_012` 约 8 度。`yellowbg`、`orangebg` 的误差都在 1 度以内。
- 7 张 `none_` 图中 5 张返回 `None`，2 张误读：`none_elevator_fade.webp` 读成 183.3 度，`none_dark_particles.webp` 读成 58.0 度。

## 限制

- 方向覆盖不均：300° 一档只有 1 张，90°、210° 各 2 张。
- 贝果场景整体偏红，黄色景物在小地图背后多呈橙色。色相落在黄色筛选范围内、面积较大的背景只有 2 张。
- `open`、`wall`、`elevator`、`redbg`、`yellowbg`、`orangebg`、`icon` 和部分 `bluebg` 来自同一晚的连续采集，地点有限。挑选时未按出生点覆盖。
- 参考方向本身有拟合误差。误差小于 1 度的差异不足以区分两个版本的优劣。
